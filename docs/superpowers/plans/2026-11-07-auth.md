# Auth Redesign Implementation Plan

> Arsip rencana implementasi. Checklist dan perintah di bawah adalah catatan saat rancangan dibuat, bukan status live. Tinjauan 7 November 2026: [status implementasi terkini](../../current-state.md).

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Align login and registration with the approved Preptiva UI and the supplied split-screen auth reference.

**Architecture:** A shared Jinja auth partial, scoped auth stylesheet, and small auth interaction script. Existing authentication endpoints and required registration fields remain the integration boundary. Reuse the current logo asset and custom dropdown.

**Tech Stack:** FastAPI, Jinja, CSS, browser JavaScript, Playwright/Chrome.

**Spec:** User reference and this document's visual direction.

## Visual direction and constraints

- Form left, warm orange brand visual right; no testimonials or unsupported social sign-in controls.
- DM Sans, charcoal text, 10px input/button radii, orange primary action, neutral borders; ENERGY 2 / RHYTHM 1 / MOTION 1.
- Use the approved Preptiva symbol at large scale on the orange field as a brand motif, without generating a new image or logo. Color transitions belong only to the reference-inspired visual panel.
- Short Indonesian copy; visible field labels, a separator before switching between login/register, responsive layout from 320px.
- Preserve name/email/password/confirmation/gender/age/consent contract. Custom gender dropdown and working password visibility buttons.
- Tests use a temporary database and no provider calls or production accounts.

## Review focus

- Existing authenticated cookies must not bring the workspace sidebar into auth pages.
- Failed requests preserve entered data and allow retry; double clicks cannot create duplicate requests.
- Password mismatch must prevent submission and recover after editing either password.
- Autofill, paste, keyboard and narrow/short screens must remain usable.
- Required registration fields must remain reachable; controls must not suggest unsupported recovery/social features.
